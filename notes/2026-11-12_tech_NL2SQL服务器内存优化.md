# NL2SQL 服务器内存优化

## 📦目标
降低阿里云 NL2SQL 常驻内存，同时保留 BGE 向量召回、业务域权限和原有会话。

## 📖讲透
向量模型类似 ETL 的公共计算组件：模型和结果向量需要保持同一套编码规则。旧实现加载 PyTorch 与句向量框架；新实现将同一个 BGE 模型导出为 ONNX，用较轻的 CPU 运行时执行。分词、去空格、小写、长度限制、CLS 提取和归一化均按原规则处理。

## 🔧选型
`AGENTFLOW_BGE_ONNX_DIR` 指向已校验的模型目录时启用轻量实现；未设置时仍走原有 BGE 实现。服务器依赖安装在独立目录，不修改上一版本的 Python 环境。缺文件、依赖或输出异常时明确报错，不把不兼容的向量当成正确结果。

## 💡可迁移
向量维度相同并不证明向量空间一致。换运行方式前，既要比较向量相似度，也要使用固定解析结果对比候选表；线上会话、账号、参考问法和自动备份需要独立验收。

## 👨‍💻代码与验证
- `metadata/index.py` 增加线程安全的 ONNX BGE 推理实现；`nl2sql/service.py` 按配置选择并复用实例。
- 本地 29 组文本，新旧向量最低余弦 0.99999964，最大绝对差约 2.7×10⁻⁷；25 组直接召回的前 4、前 8 表顺序均一致。
- 使用 200 道已有题目的解析记录，等间隔抽取 50 道重放：新旧候选表顺序 50/50 相同，标准表进前 4 均 41/50、前 8 均 45/50。这是召回对照，不等同于 SQL 正确率。
- 服务器独立进程复算 32 条既有字段向量，最低余弦 0.99999982；轻量运行时进程峰值约 255 MiB，没有加载 PyTorch。
- 本地完整回归 2042/2042；服务器隔离权限与模型选择测试 18/18。切换后核对管理员、业务一、财务的可见范围、参考问法、现有模型、历史会话、实际登录和退出；自动备份执行成功。
- 前后快照：原主进程 RSS 约 891 MiB、新版约 715 MiB；服务内存统计约 1,057 → 887 MiB；整机可用约 410 → 521 MiB。不同时间及文件缓存状态会影响数值，不能把差额当成稳定保证。
- 上线后连续切换四个业务域两轮，8/8 请求成功，单次最慢约 0.35 秒；服务未出现内存高阈值或 OOM 事件。该检查不代表并发性能或完整模型问答时延。
- 当前线上版本 `workspace-20261112-onnx-memory`；切换前代码、配置及会话备份保留。服务器启动配置引用独立的模型和运行时目录；后续清理旧版本时需同时核对这些依赖。

## ⚠️常见坑
本次没有调用真实大模型或连接真实业务数据库，没有做并发和端到端 SQL 质量验收。服务器仍运行 SQLite 模拟数据。单次内存快照不能证明未来负载不会触及阈值；现有服务上限和自动备份保持启用。
