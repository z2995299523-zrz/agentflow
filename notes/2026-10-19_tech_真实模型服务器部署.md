## 📦 目标

将模拟专题库切换成真实专题库的表结构、字段、血缘、加工 SQL 和 BGE 向量。保留原模拟资料与历史会话，新增密码保护和独立真实会话库。项目仍只生成并校验 SQL，没有连接单位数据库，也没有上传业务记录。

类比 ETL：本次更换的是程序使用的数据字典和加工血缘，不是把生产事实表复制到演示库，更不是启动一套生产加工任务。

## 📖 讲透

代码版本、资料版本、模型调用配置和会话状态分别保存。代码来自 Git；真实资料由清单、SQL 和 SQLite 元数据库组成，单独打包；访问密码和 DeepSeek Key 留在 Git 外；两套资料的会话分开。

真实元数据库通过 SQLite 在线备份取得一致性快照，包内每个文件登记 SHA256。服务器安装到新目录后，逐文件核对摘要，并检查完整性、表字段数量和 BGE 向量数量。安装完成才允许准备新代码与资料契约，准备完成才切换配置和代码指针。

稳定路径为 `/var/lib/agentflow/history-real.db`，资料版本中的 `build/history.db` 链接到它。旧 `/var/lib/agentflow/history.db` 继续保存模拟会话。类似不同 ETL 业务域的运行流水分别保管，避免更换资料后把旧领域的问答当作新领域上下文。

## 🔧 选型

- 继续使用现有 Nginx、systemd 和 Python 3.12 环境，没有新增 Docker。
- HTTP Basic Auth 覆盖首页、静态文件和 `/api/`；凭据不进 Git，代码模板通过外部 include 保留认证。
- 将本机已计算的 22,730 条 BGE 字段向量随元数据库传输，不在约 2 GB 的服务器上重算整套向量。
- 真实资料强制 `EXECUTOR=none`，发布时阻止与 DuckDB 模拟执行器混用。
- 备份服务读取 `AGENTFLOW_HISTORY_DB`，随资料配置切换到真实会话，激活前仍先备份旧资料会话。

## 💡 可迁移

“测试通过”“发布成功”“语法正确”“业务口径正确”对应不同层次的验收。就像 ETL 程序退出码为零、分区有数据，不代表金额口径已经正确对平。

本次首次立项统计生成 SQL 并通过静态校验，但把申报日期当作立项日期，属于业务口径偏差。明确追问“只统计正式立项，不能用申报日期近似”后，才选回原评估确认的项目表。两次结果均保留，不能将第二次通过解释成所有立项问法都已正确。

资料与代码分别版本化，也让回退可解释：切回模拟资料会重新显示旧模拟会话，真实会话仍留在独立文件中。回退代码不等于恢复旧数据库覆盖新记录。

## ⚠️ 常见坑与验收边界

- 真实资料只生成 SQL 时，`exec_result` 可以为空，不能强行读取 `executed` 字段后把验收脚本报错当作部署故障。
- SQL 静态检查没有验证真实数据值或业务口径；立项和申报混用的问题已经记入交接，后续若优化生成规则，应按完整评估流程处理。
- 本次授权的出站目的地是 `api.deepseek.com`，内容是命中的模型名称、字段说明、加工表达式和血缘证据，不包含业务记录和数据库密码。不要据此扩大出站范围。
- 资料包按白名单只收四类标准清单、SQL 和元数据库，不收额外 CSV、本地会话、评估题、转换配置或密钥。
- 当前只做了实际发布和重启持久性检查，未执行一次真实线上回退；回退流程和旧版本认证保留逻辑已写入交接，不能说回退已实测。
- 浏览器 390 像素宽度仍有约 6 像素横向溢出；未做手机实机验证。访问密码共用，登录后会话仍是共享模式。
- 每日备份为服务器本机副本，不能替代离机备份；真实资料不在 Git 中，恢复资料需要保留的私有资料包及本机原资料。
