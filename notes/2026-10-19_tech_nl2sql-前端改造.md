# NL2SQL 前端改造：React + Ant Design 替换 Streamlit，SSE 流式进度、会话历史、血缘连线图

> 用户定的四件事：React + Ant Design；前后端分开部署；会话历史存数据库（先用 SQLite）；字段血缘画成节点连线图。

---

## 📦 目标

Streamlit 版功能都能用，但一看就是「脚本拼出来的页面」：每次点按钮整页重跑、刷新就丢对话、血缘是缩进文本。这一轮换成正经的前端，并且功能不少于原来：

| 页面 | 原来（Streamlit） | 现在（React） |
|---|---|---|
| 查数 | 状态框里一行行打印进度 | 七步进度条边跑边亮，下面列每一步的摘要；接口刚启动、某一步很慢时说明原因 |
| | SQL 代码块 | 高亮、行号、复制按钮，标出静态校验是否通过 |
| | 口径说明等一段段往下排 | 口径说明、执行结果、用表与字段、运行过程分标签页；用到的表和字段能点进元数据页 |
| | 反问选项是按钮 | 选项做成卡片，写明对应哪个字段、怎么加工；回答过的反问变灰 |
| | 会话存在页面里，刷新就没了 | 会话历史存进 SQLite：左侧按今天、昨天、更早分组，能搜索、改名、删除，刷新、重启都在 |
| | 执行结果整表铺开 | 分页（10/20/50/100 条一页）、导出 CSV，金额加千分位 |
| | 输入框示例写死成模拟库的问题 | 通用的提示文字；欢迎页列出当前资料样例库里的问法，真实库没有样例就给通用的提问建议 |
| 元数据 | 下拉框选层级、选表、选字段 | 左侧按层级筛表、搜表和字段（服务端搜，真实库两万多个字段）；右侧字段清单带每个字段的血缘条数 |
| | 缩进文本画上下游 | 节点连线图：上游在左、下游在右，点连线看这一跳的表达式、过滤和关联条件，双击字段以它为中心重新展开 |

## 📖 讲透

### 1. 前后端分开：浏览器只认一个地址

界面是一堆静态文件（HTML、JS、CSS），接口是 FastAPI。浏览器访问界面的地址，界面里所有请求都发到 `/api/...`，由中间那一层去掉 `/api` 转给接口：

- 开发时是 Vite 开发服务器（5173，改代码热更新）
- `start.bat` / `start.sh` 用 `vite preview` 托管构建产物（8080）
- Docker 里是 nginx（`web/nginx.conf`）

ETL 类比：前置机转发。业务系统只连前置机，前置机按路径把请求转给后面的服务；浏览器看到的始终是同一个地址，所以不用配跨域（CORS）。接口的路径一个没改，`/docs` 和老的 `POST /nl2sql/query` 照常用。

### 2. SSE：把七步进度推给浏览器

一轮查询要 5～10 秒，三步调模型。要让用户看到「走到第几步了」，有三种办法：

| 办法 | 怎么做 | 类比 |
|---|---|---|
| 轮询 | 浏览器每秒问一次「跑完了吗」 | 每隔几秒查一次作业状态表 |
| SSE | 一次请求，服务端每走完一步往回写一条 | `tail -f` 跑批日志 |
| WebSocket | 双向长连接 | 两边都能随时发消息的专线 |

只需要服务端单向推、推完就结束，选 SSE。接口 `POST /conversations/{id}/turns` 返回 `text/event-stream`：

```
event: step
data: {"step": "parse", "label": "① 需求解析", "elapsed_ms": 1364, "summary": "完整需求：……"}

event: step
data: {"step": "recall", ...}

event: turn
data: {"turn": {存下的这一轮}, "context": {下一轮的上下文}}
```

三个细节：

1. **流水线是同步代码，放后台线程跑**。事件循环这边等队列，有一条发一条（`main._event_stream`）
2. **保活**：一次模型调用可能几十秒没有输出，nginx 默认 60 秒没数据就断开。15 秒没有新事件就发一行 `: ping`（冒号开头是注释，浏览器忽略）
3. **浏览器用 fetch 读流，不用 EventSource**：EventSource 只能发 GET，而提问要用 POST 带请求体。`web/src/api/client.ts` 边读边按空行切分事件

浏览器中途关掉页面，后台线程照样跑完、照样把这一轮存进会话历史，回来刷新就能看到。

### 3. 会话历史：上下文由服务端算

原来追问的上下文（上一轮的完整需求、还没回答的反问）存在 Streamlit 的会话里，由界面带给流水线。现在会话存进 SQLite（`资料目录/build/history.db`，两张表：`conversations`、`turns`），浏览器只发「在哪个会话里问了什么」，上下文由服务端从存下的轮次里算：

> 最近一个有完整需求的轮次，它的需求就是 `prev_requirement`；它如果是反问，它的反问就是 `prev_clarify`。

和原来界面的规则一模一样（解析失败、不是查数需求的轮次不动上下文）。ETL 类比：断点续跑时，从作业运行记录里找最近一个成功的批次，从它往下接。

流水线本身仍然无状态，评估、老的 `/nl2sql/query` 不受影响。存储层（`nl2sql/history.py` 的 `ConversationStore`）只暴露建、列、取、改名、删、记一轮、算上下文七个方法，接口层不碰 SQL；以后换 MySQL、PostgreSQL 只换这一个类。每套资料一个库文件：真实库的会话历史落在 `data/real_mart/` 下面，和真实资料一起不入库。

### 4. 血缘连线图：按跳数分列

接口给的血缘是一跳一跳的（target 由 source 加工而来，带 depth）。排版（`web/src/utils/lineageLayout.ts`）：

- **分列**：上游第 d 跳的来源放第 -d 列，下游第 d 跳放第 +d 列，选中的字段在第 0 列。同一个字段出现在好几跳里时放离中心最近的那列
- **列内排序（重心法）**：从中心往外一列一列排，每个字段按「和里面一列相连的字段的平均位置」排序，连线交叉少
- **合并**：同一对字段之间的多条血缘（两个脚本都写了它）合成一条线，点开能看到全部

连线颜色：虚线是直取，蓝线有加工表达式，橙线带过滤或关联条件——一眼就能看出口径在哪一跳被「加工」了。打开时让中心字段前后两跳占满画布、缩放不小于 0.4，更远的拖动或看右下角的小地图。

### 5. 一个藏了很久的锁问题

实测第一问时发现：流水线第一次装配要导入模型库（机械盘上两三分钟），这期间 `/health`、会话列表、元数据接口全部卡住。原因是 `service.get_pipeline()` 装配时一直占着缓存的锁，而元数据、会话历史也要拿这把锁。Streamlit 时代一次只做一件事，看不出来；新界面打开就同时发好几个请求，立刻暴露。

改法：装配用单独一把锁，缓存的锁只在读写缓存变量时短暂持有。ETL 类比：别在长事务里一直锁着配置表，否则别的只读查询全在排队。另外接口启动时在后台线程预热（装配流水线、加载 BGE），第一问不用等冷启动。

## 🔧 选型

| 问题 | 选择 | 理由 |
|---|---|---|
| 前端框架 | React 19 + TypeScript + Vite 8 + Ant Design 6 | 国内企业后台最常见的组合；Ant Design 的表格分页、标签页、步骤条、弹窗都现成；TypeScript 把接口的数据结构写成类型，接口改了编译就报错 |
| 部署 | 前后端分开（用户定的） | 界面和接口各自升级、各自扩容；生产环境用 nginx 托管静态文件、转发接口，是最常见的做法 |
| 进度推送 | SSE | 单向推送、自带「一条条事件」的格式，比 WebSocket 简单，比轮询及时 |
| 会话存储 | SQLite，每套资料一个库 | 用户说先用 SQLite；不用 SQLAlchemy，标准 SQL 加一个类，换库成本低 |
| 血缘图 | React Flow + 自己排版 | 用户选了连线图；排版按跳数分列，比通用的 dagre 更贴合「上游在左、下游在右」，也少一个依赖 |
| SQL 高亮 | highlight.js 只注册 SQL | 体积小；输出已经转义过 |
| 版本 | 写死版本号，选发布满两周的 | 防止刚发布就被投毒的包；`package-lock.json` 入库，`npm ci` 装的版本一致 |

TypeScript 用 5.9 而不是最新的 7.0（Go 重写的版本），图稳：类型检查这点规模用哪个都快。

## 💡 可迁移

- **长任务的进度**：任何「几秒到几分钟」的后端任务（跑批、报表导出、模型推理），都可以用「后台线程 + 队列 + SSE + 保活」这一套推进度
- **状态放哪**：能由服务端从记录里算出来的状态（上下文），就不要让浏览器带来带去；浏览器只管展示
- **锁的粒度**：缓存的锁只保护「读写缓存」这一下，耗时的构建放到锁外面或者单独一把锁
- **验证要用真实的并发**：单元测试里一次只调一个接口，锁的问题测不出来；用真界面走一遍才看到

## ⚠️ 常见坑

1. **antd 的 `<App>` 多包一层 div**：`#root > .ant-app` 也要 `height: 100%`，flex 列里能滚动的那块要 `min-height: 0`，否则整页跟着内容变高，页头被滚出去
2. **SSE 过代理会被攒着**：nginx 要 `proxy_buffering off`、读超时放长；接口回 `X-Accel-Buffering: no`
3. **输入法选字时的 Enter 不能发送**：判断 `event.nativeEvent.isComposing`，否则拼音还没上屏就发出去了
4. **金额别转浮点**：DuckDB 的 DECIMAL 转成 JSON 是字符串，前端按字符串加千分位，转成数字可能丢精度
5. **复制按钮在局域网 IP 下失效**：剪贴板接口只在 https 或 localhost 下可用，要退回到「选中文本再复制」
6. **内置浏览器的窗口在后台时页面不渲染**：React Flow 量不了节点尺寸、不画连线，弹窗的关闭动画也停住，看起来像 bug；验证截图时让窗口在前台

📌 **面试中怎么说**：界面从 Streamlit 换成了 React + Ant Design，前后端分开部署。查数一轮要五到十秒，我用 SSE 把七步进度一步步推给浏览器，流水线在后台线程跑，十五秒保活一次防代理断开。会话历史存 SQLite，追问的上下文由服务端从会话记录里算，浏览器只发「在哪个会话里问了什么」，流水线本身保持无状态。血缘图按跳数分列、用重心法排序减少交叉，点连线能看到这一跳的加工表达式和过滤条件。上线前用真界面走了一遍，发现装配流水线时一把锁让所有接口卡住两三分钟，拆成两把锁之后响应回到毫秒级。
