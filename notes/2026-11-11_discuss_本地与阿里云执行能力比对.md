# 本地、Git 与阿里云执行能力比对

## 📦 目标

核对本地为何没有查询结果，以及代码是否落后于 Git 和阿里云。

## 📖 讲透

同一个 ETL 程序可以通过运行参数切换数据源：执行器代码存在，不代表当前进程启用了执行。本地接口 `EXECUTOR=none`；阿里云运行进程为 `EXECUTOR=sqlite`，连接按元数据生成的 SQLite 测试数据，并非真实业务库。

## 🔧 版本与配置

- 2026-11-11 GitHub 的 `codex/agentflow-server-deploy`、本地 HEAD、阿里云活动发布目录均为 `a304b94a54a41895c5c1e91cb887c777cd4cb91c`。服务器该发布目录是快照，非 Git 工作树；对六个关键文件，服务器文件摘要与本地该提交一致。当前本地另有未提交的模型设置与会话选择改动。
- GitHub `master` 为 `aa753f94b79c025802f6d3f1cff32f9bdd89ff94`，本地工作分支比它多 42 个提交；执行和图表功能 `5af7e2f` 已在当前分支。
- 用户要求切换真实元数据时，本地被设置成只生成 SQL，导致页面隐藏执行开关。阿里云实际运行的是测试数据执行模式；先前基于旧部署文档推断其为 none 不准确，以本次进程运行配置为准。
- 本地和阿里云测试数据库的 SHA-256 相同，均为按元数据生成的模拟数据。两边 quick_check 通过；本地最新元数据 1728 张表在测试库均存在，字段结构核对缺失 0。结构核对不代表查询口径或每个 SQL 都能执行。
- 本地与服务器元数据库不是相同文件，虽然同为 1728 张表、43993 字段，血缘、关联和样例数量不同，因此不能认为资料版本一致。

## 💡 可迁移

分别检查代码版本、进程配置、数据文件和表字段结构，才能判断是缺功能还是没有启用功能。真实元数据只描述结构，不等于连接真实业务库。

## 👨‍💻 代码

`nl2sql/executor.py` 支持 none、DuckDB 和 SQLite；`nl2sql/workflow.py` 仅在 SQL 校验成功且请求允许执行时调用执行器。SQLite 执行器只读并明确标注模拟数据。

## ⚠️ 常见坑

本次比对未执行业务 SQL，也未改变服务器或本地执行模式；本地静态检查不证明真实业务数据查询、数据准确性或业务验收。若希望本地与阿里云一样展示模拟查询结果，可以将本地执行模式设为 sqlite 并重启本地接口，不能把模拟结果当作业务数据。

后续用户授权后，本地执行模式已改为 sqlite 并重启，仍使用真实元数据和本机模拟测试库；健康检查正常，执行器只读 `SELECT 1` 成功。未调用大模型或执行真实业务查询。
