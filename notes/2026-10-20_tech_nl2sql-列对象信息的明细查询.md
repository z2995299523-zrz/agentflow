# NL2SQL：「列出某类对象的信息」被判成不是查数需求——第 ① 步补上列明细这种需求

> 2026-10-20 线上反馈：真实库上问「我想查询××人员的信息」，界面提示「这不是一个查数需求」，可专题层明明有这张表。

---

## 📦 目标

- 复现、找根因，让「只列某类对象的信息、名单、明细」按明细查询走完七步
- 不能放宽过头：问候、改数据、连对象都没说的照样拒；计数、追问、缺对象时的反问不能被改坏
- 用数字说话：① 的新旧对照、真实库端到端、模拟库 40 题回归

---

## 📖 讲透

### 1. 复现：一个根因，两种错法

第 ① 步不读元数据（解析只管理解需求，找表是 ② 的事），本机和线上的代码一致，所以在本机直接用 DeepSeek 单跑 ①，每种问法 3 次：

| 问法 | 上一轮 | 旧提示词的结果 |
|---|---|---|
| 我想查询××人员的信息 | 无 | 3 次都算查数需求，但指标编成「××人员数」，后面会写成数人数的 SQL |
| 我想查询××人员的信息 | 有（查立项项目数） | 3 次都判成不是查数需求 ← 线上就是这种 |
| 查询××人员信息 | 无 | 3 次都编成计数 |
| ××人员信息、查一下××人员 | 无 | 6 次都判成不是查数需求 |

根因在 ① 的契约只认「指标」。提示词的规则和示例全是余额、计数：「明细查询也要写一个最主要的度量字段作指标」「连要查什么都没说也按不是处理」，拒绝回复的示例还写着「请告诉我想查哪个指标」。人员信息没有度量字段，模型只有两条路：编一个计数凑指标，或者判成不是查数需求。

有上一轮时更容易走第二条路：追问规则只写了「本轮输入是完整需求（有指标有时间）时忽略上一轮」，本轮既不「完整」、又和上一轮接不上，模型就拒了。

ETL 类比：报表需求登记表只设计了「指标」一栏。业务来要一份人员花名册，登记的人要么硬填一个「人数」，要么退回去说「这不是报表需求」。该做的是让登记表认得清单类需求：对象写进指标栏，注明不是计数。

### 2. 改了什么（只改 ①）

`prompts/nl2sql.py` 的 PARSER_SYSTEM 四处：

1. **is_query**：只说了要看哪类对象的信息、名单或明细（「查询客户经理的信息」），也是查数需求，是明细查询，不要因为没说指标就判成不是；「连要查什么都没说」改成「既没说指标，也没说要看哪类对象」
2. **metrics**：只列对象本身的信息、没有要看的度量时，指标写对象的叫法，entity 留空——这是列明细，不是计数，不要写成「客户经理数」；原文点名的字段写进 dimensions，没点名就留空，假设写「没说要看哪些信息，按客户经理的基本信息列出」
3. **追问**：本轮要看的是另一类对象、和上一轮接不上时，按新需求解析，忽略上一轮
4. **示例**：带一个不相干的上一轮（合同数），本轮「查询客户经理的信息」→ 指标「客户经理」、不带被计数的实体、不带上一轮的条件。拒绝回复的示例也补了「或者要列出哪类对象的信息」

`nl2sql/parser.py` 的 check_parsed：模型漏写指标时的重试提示原来是「用户连要查什么指标都没说，请把 is_query 改成 false」。这句话会把一个本来该列明细的需求推成「不是查数需求」。改成「既没说指标、也没说要看哪类对象」才改 false，并说明列对象信息时指标怎么写。

**为什么指标写对象的叫法，不写「××信息」「××数」**：② 的关键字召回把检索词切成字二元组，比字段名（权重 0.7）和表名（0.3）。对象的叫法和表的中文名一样时，整张表的字段都加分；写成「××信息」会多出「信息」这个二元组，库里叫「××信息表」的表很多，是噪音；写成「××数」，④ 会看到「被计数的实体」去写 COUNT。

### 3. 后面几步不用改

④ 的核对不要求有「指标」用途的字段，R1–R9 也没有要求汇总的规则，列明细的 SQL 能直接走通。真实库端到端的结果（见文末）：④ 自己选了粒度正好是这类人员的那张表，列姓名、职称这类基本信息，没列 ETL 时间这类技术字段，连「两个恒为空的标志字段不列」都写进了假设。

## 💡 可迁移

- **意图识别的拒识边界要写成「缺了什么」，别写成「没填某个槽位」**。槽位是按常见需求设计的，用户的需求类型比槽位多；拒识条件写宽了，没想到的需求类型全被拒
- **重试提示也是提示词**。校验不合格时告诉模型怎么改；改法里如果有「那就改成拒绝」，条件要写窄，否则重试就成了拒绝的后门
- **few-shot 要覆盖需求类型，不只覆盖句式**。示例全是余额和计数，模型就以为只有这两类；补一个列明细的示例，比在规则里多写三句话管用
- **解析和找表分开，各管各的**。「元数据里明明有这张表」是 ②④ 的事；① 只要别把「列对象信息」当成没说要查什么

## ⚠️ 常见坑

1. **「信息」和「情况」不一样**：「××的信息」按基本信息列出；「××的情况」看哪些指标还是没法默认，照旧可以反问（新提示词下 3 次里 2 次反问、1 次按列明细，两种都能接受）
2. **指标别写成「××数」，也别写成「××信息」**：前者会被当成计数，后者给召回加噪音
3. **真实库的例子不进入库文件**：提示词、测试、笔记里一律用虚构对象（客户经理）；真实问法只放在不入库的 `data/real_mart/eval_listing.yaml`
4. **只改了本机，线上要发布才生效**：服务器按指定的 Git 提交发布，先提交、推送，再按部署手册走
