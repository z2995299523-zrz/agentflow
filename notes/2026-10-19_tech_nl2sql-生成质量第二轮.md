## 📖 讲透

### 1. 码值：给代码字段配上「字典表」

ETL 里一张事实表的 `industry_cd` 存的是代码，业务人员说的是「制造业」。写过报表的都知道要么关联行业代码表按名称过滤，要么查码值写 `industry_cd = 'C'`。模型不知道这一点：字段清单里 `industry_cd`（行业代码）没有码值说明，同表的 `industry_nm`（行业名称）和它之间也没有任何文字联系。

做了三层，和跑批的「字典表关联 + 数据质量检核」是一回事：

1. **证据里配对**（`metadata/codes.py`）：中文名「××代码 / 编码 / 编号 / 号」配「××名称」，英文名 `_cd / _code / _no / _id` 配 `_nm / _name`。同表有名称字段的标「名称字段：industry_nm」，同表没有、证据里有码值表的标「码值表：ods.industry_dict.industry_nm」
2. **提示词**：④ 加规则 13、⑤ 改方言规则 10——过滤值是中文名称就用名称字段，代码字段只和码值说明里的代码比
3. **校验兜底 R9（错误）**：代码字段和纯中文字面量比较（`=`、`<>`、`IN`、`LIKE`），并且能确定它存的是代码（同表有名称字段、码值说明里查得到这个名称、或有码值表）时报错，错误里直接写「改用同表的 dim.corp_cust.industry_nm」，走现有的修正回路

真实库的字段清单有 5856 个代码样的字段、一个码值说明都没有，其中 1300 个左右能按英文名配上名称字段——证据里的配对提示在真实库上比码值说明更有用。

### 2. 方案精简：去掉只用来关联的维表

C 组的 SQL 常常是 `FROM ads.corp_cust_dep_bal_d JOIN dim.corp_cust ON …`，维表一个字段都没取。结果没错，但多一次关联，审 SQL 的人也会犯嘀咕。④ 之后加了一步确定性的 `prune_plan`：

- **孤立表**：没有字段、不在关联里、过滤条件里也没写到 → 去掉
- **只用来关联的维表**：只引用了关联键、关联键包含维表的全部粒度（N:1，不会发散）、不是中间表，并且另一侧是专题层的表（专题层与维表参照完整，ETL 保证），或者它在 LEFT JOIN 的右边 → 去掉

**整合层、贴源层的表内连接维表不动**。U01–U03 的标准答案就是「整合层明细 + 只用关联键的 `dim.corp_cust`」：专题层加工时用内连接把非对公客户过滤掉了，下钻到明细查数时要把这个内连接还原出来。这里的内连接是过滤条件，不是多余的关联——好比从明细层重算汇总数，得把汇总作业里的 `INNER JOIN` 原样带上，数才对得上。

第一次改完重跑发现：方案确实去掉了维表，但 ⑤ 看着样例 SQL 又把关联抄了回来（C 组 8 次）。所以去掉的表记进方案的 `dropped_tables`：⑤ 的消息里写「不要用的表」，SQL 再用就是 R8 错误，进修正回路。

### 3. 反问：哪些是口径分岔、哪些不是

④ 的规则 3 改了三处：点名常见分岔（含不含某类账户、是不是全口径、日均的统计区间）；口径线索只说清一部分时，没说清的照样问；能反问时不许把口径选择写成假设——「要写『需求没说明……按最常用的……』，就说明该反问」。

第一次改完还加过一句「判断分岔要看全部候选表」，结果 B 组把「活期存款余额」和「总的存款余额」放在一起反问（B08、K04 多问了），第二次删掉，改成「不同的指标不算分岔，点名了某一类就直接用它」。

A05（只说「日均」）提示词改了两轮，B、C 组都没问出来：模型先按「汇总程度最高」选了机构汇总表，那张表只有年日均，看不到月日均。最后改成确定性判断（`planner.clarify_daily_average`）：需求只说「日均」、方案挑了一种、证据里还有同一指标别的统计区间（中文名去掉「年 / 月」后相同），就改成反问，选项按区间列出对应字段。只看中文名，三组一样。

### 4. ① 也能反问

真实库的 R01 要看某一个对象的明细：说了查什么，只是没说是哪个对象。原来 ① 只有「是 / 不是查数需求」两种结论，就判成了不是。现在 `ParsedRequest` 加了 `clarify`：缺了没法默认的要素（单个对象没说是哪个、只说「情况」）时，① 直接反问，第一个选项是最常见的理解（列出全部），流程不进 ②，直接到 ⑦。用户回答后 ① 不能再问；回答是「按最常用的口径处理」这类时按第一个选项理解，写进假设。口径分岔仍归 ④。

## 🔧 选型

| 问题 | 为什么这样改 |
|---|---|
| 码值 | 证据加提示、提示词约束都是「劝」，R9 是「拦」。R9 只在能确定存的是代码时报：带数字、字母的字面量不查（合同编号里也可能有汉字），码值说明里登记的取值本身就是中文的也不报 |
| 多余维表 | 提示词里本来就写了「没用到维表字段就不要关联」，模型照样关联；去掉的依据是确定的（N:1、参照完整），交给代码 |
| 反问 | 一般性的口径分岔仍靠提示词（模型要读加工链路才知道「存款余额」不含保证金）；日均区间这种只看中文名就能判断的，交给代码 |
| ① 反问 | 改契约（`ParsedRequest.clarify`）而不是放行给 ④：④ 的反问只管口径分岔，「哪个对象」在 ① 就能问，不必先召回、组证据 |

## 💡 可迁移

- **先看逐题记录再改**：四个问题的根因都是从 ④ 的输入输出里查出来的（证据里有没有这个信息、模型是怎么想的），不是猜
- **「劝」和「拦」分开**：提示词管理解，确定性代码管能判断的事（配对、精简、区间），校验器兜底。模型不听劝的地方（照抄样例、不问日均），换成代码
- **改完要量，量完常有意外**：精简方案被 ⑤ 抄回来、「看全部候选表」引出多余的反问，都是第一次重跑才看到的

## ⚠️ 常见坑

1. **只用关联键的内连接不一定多余**：从整合层明细查数时，它可能是在还原专题层加工时的过滤，不能一刀切
2. **方案去掉了，SQL 还会加回来**：⑤ 也看样例，样例里有的关联它会照抄，要在 ⑤ 的消息里写明并在校验里拦
3. **给 ⑤ 的表结构里不能指向方案外的表**：「码值表：dim.corp_cust.cust_nm」这类提示在 ⑤ 的表结构里要去掉，否则等于提醒它关联
4. **提示词加一句可能引出新问题**：「看全部候选表」本意是让模型看到月日均，结果让它把活期和总余额也当成分岔
5. **评估有波动**：35 道题每道约 2.9 个百分点，同一份代码两次运行可以差两三道题，所以这一轮跑了两次

## 数字对照

模拟库 40 题，A 仅模型结构 / B 加血缘 / C 加血缘和样例。「第一次改完」是按计划改完的第一次重跑，「最终」是补了三处之后的两次运行（同一份代码跑两次，看波动）。报告都在 `eval/reports/`，首轮报告没动。

|---|---|---|---|---|
| 执行准确率 A / B / C | 82.9 / 80.0 / 97.1 | 77.1 / 88.6 / 97.1 | 85.7 / 100 / 97.1 | 82.9 / 91.4 / 97.1 |
| 选表完全一致 A / B / C | 74.3 / 77.1 / 62.9 | 74.3 / 80.0 / 65.7 | 85.7 / 94.3 / 85.7 | 82.9 / 91.4 / 80.0 |
| 选表包含标准用表 A / B / C | 80.0 / 91.4 / 94.3 | 80.0 / 88.6 / 94.3 | 91.4 / 100 / 97.1 | 85.7 / 97.1 / 97.1 |
| 字段准确率 A / B / C | 82.9 / 91.4 / 94.3 | 80.0 / 91.4 / 94.3 | 91.4 / 100 / 97.1 | 85.7 / 100 / 97.1 |
| 反问准确率 A / B / C | 95.0 / 95.0 / 97.5 | 100 / 90.0 / 97.5 | 97.5 / 97.5 / 100 | 97.5 / 97.5 / 97.5 |
| 平均 token A / B / C | 14624 / 26279 / 27901 | 15533 / 27261 / 28219 | 16065 / 27007 / 29058 | 15837 / 27465 / 29222 |

单位是百分比，token 是每题平均。怎么读：

- **码值**：D06、F04 三组都用了 `industry_nm`，方案的假设里写着「按名称字段过滤」；R9 两次运行都没触发，模型第一次就写对了，R9 是留着兜底的
- **选表完全一致**：C 组 62.9% → 80.0%～85.7%，B 组 77.1% → 91.4%～94.3%。方案精简在一次运行里触发 10 次，⑤ 一次都没再加回来。剩下的多关联主要是方案里取了机构名称、多输出了一列（B06、K03），和整合层明细关联客户维表（U04，按设计保留）
- **执行准确率**：B 组 80.0% → 91.4%～100%；C 组不变（唯一的错题 U05 一直错）；A 组持平（82.9%～85.7%），A 组没有血缘，错的多是向上溯源和「年日均本来就不含保证金」这类要看加工链路才知道的口径
- **反问**：A05 三组都问了（确定性判断）；B08、K04 不再多问；A04（含不含保证金）还不稳定：最终两次运行里 A、B 组都没问，C 组一次没问
- **token**：每题多 1%～5%，来自证据里的名称字段提示
