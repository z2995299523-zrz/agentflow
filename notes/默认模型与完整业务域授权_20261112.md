# 默认模型与全授权业务域

## 📦 目标
查数页面不再要求用户选择模型或业务域；管理员维护默认模型，每次查数使用账号当前的全部业务域授权。

## 📖 讲透
类似 ETL 调度统一指定连接，模型在每轮请求开始时由服务端确定；旧会话中保存的模型不会覆盖当前默认值。多域用户的表范围是各授权域的并集，管理员保持全部表权限。欢迎页参考问法也根据完整授权范围筛选并轮流展示。

## 🔧 选型
受控模式在服务端解析默认模型并忽略旧版查数模型和域参数，避免只隐藏界面而让旧客户端绕开规则。旧的会话模型读取接口返回当前默认值，写入接口对已授权会话返回 403；无登录的旧模式保留原 API 兼容行为。模型不可用时沿用现有可用模型回退规则，均不可用时报错。

## 💡 可迁移
把权限范围理解为数据仓库的行列访问范围：前端只负责展示，实际授权边界和连接选择应在服务端执行；权限变化后应重新判断旧会话能否访问。

## 👨‍💻 代码
`main.py` 统一选择模型和授权范围；`web/src/state/chat.tsx` 不再传会话模型或业务域；查数页去掉选择器；模型配置页解释默认值对后续查数生效。历史消息保留原来的模型记录。

## ⚠️ 常见坑
配置的新默认模型只影响之后开始的查数，不会中途切换运行中的请求；默认模型需要启用、连接配置完整且在服务端批准范围内。客户端携带旧参数也不会收窄或扩大授权。参考问法依然只展示当前有权访问的内容，不应把它误当成真实 SQL 验收。
