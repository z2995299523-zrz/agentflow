# AgentFlow 用户模块与业务域权限设计

## 📦 目标与一期范围

用户登录后，系统按其获批业务域限制元数据、查数和历史会话。项目人员默认只能使用项目域，经费管理人员默认只能使用经费域。业务确有需要时，可为同一账号同时授权两个域，也可设置授权到期时间。

一期按表授权。每张可查询表归属一个业务域，公共维表归入单独的公共域，经确认后授权给相应用户。行级和字段级控制留给后续需求。包含不同可见范围数据的混合表，先由数据负责人确认可开放范围，必要时发布专用视图，再纳入授权。

## 📖 业务规则

把它看成一张数据权限映射表。以用户 ID 找到有效的业务域授权，再以业务域代码关联表清单，得到本轮允许访问的表。组织和岗位可以用于查找人员或生成授权建议，生效以实际授权记录为准。

| 用户 | 有效授权 | 可以查询 |
| --- | --- | --- |
| 项目人员 | 项目域 | 项目域表 |
| 经费管理人员 | 经费域 | 经费域表 |
| 兼岗人员 | 项目域、经费域 | 两域各自的表。允许跨域关联时，关联两边都要在授权内 |
| 授权到期或未分配业务域 | 无 | 可以登录查看账号状态，查数和业务元数据入口受限 |
| 系统管理员 | 管理功能。查数范围按其业务域授权计算 | 管理用户、授权和模型连接。按所获业务域权限查询 |

一个查询涉及的每张底层表都须获授权，包括子查询、CTE 和关联表。权限不足时整条查询中止，避免遗漏口径后返回部分结果。例如，项目域账号可以查询项目立项数量。计算项目经费执行率若需要读取经费支出明细，就提示当前范围无法完成该问题。

公共维表和跨域视图都作为有归属的表治理。公共域仅纳入经过审核的通用维度。跨域视图的授权依据是它实际暴露的数据，发布前审核来源和输出范围。表的血缘关系可以用于分析影响，业务域权限由显式归属和授权记录决定。

## 🔧 数据、页面与运行方案

### 元数据与授权

本地 SQLite 元数据库的 `meta_table` 有 1,728 张表。该表及当前的表清单模板都缺少独立业务域字段。现有唯一表标识为 `schema.table`。建议在元数据表清单增加「业务域代码」，导入时校验并写入元数据快照。若上游已经维护归属清单，可按 `schema.table` 批量导入。允许按模式名或前缀提出归属建议，由负责人确认后发布。未归类的表默认不可查询，只出现在管理员的待归类清单。

| 记录 | 建议字段 | 维护方式 |
| --- | --- | --- |
| 用户 `users` | 用户 ID、登录账号、姓名、部门、账号状态、管理角色 | 管理员新增、停用和维护账号 |
| 业务域 `domains` | 域代码、名称、负责人、启停状态 | 按业务定义维护。代码保持稳定 |
| 人员域授权 `user_domain_grants` | 用户 ID、域代码、开始时间、到期时间、授权人和撤销记录 | 管理员批量或单人授权。一个用户可拥有多个域 |
| 表归属 `meta_table.domain_code` | 完整表标识、域代码 | 随元数据快照导入，记录覆盖率及变更清单 |
| 会话归属和访问记录 | 会话所属用户、每轮用到的受控表、当时的元数据和授权版本 | 随会话写入，用于续问、权限变更后的历史检查和审计 |
| 权限审计 | 操作者、目标、时间、动作、授权前后值、允许或拒绝结果 | 记录授权、撤销和越权拒绝，省略凭据及查询结果 |

人员和域授权先存应用可写的 SQLite 管理库，表归属随元数据版本发布。旧快照兼容读取，未录入域归属的表按未归类处理。导入预览列出新增表、归属变更和未归类表。无效域代码、同表冲突映射须修正后再发布。元数据热更新后，新请求自动使用新快照。已停用账号、已撤销和到期授权在后续请求中立即失效。

### 页面

- **登录与账号**。页面显示当前用户和已授权业务域。试点由管理员建号，使用应用会话；如已有统一身份平台，可接入其登录并复用同一套授权。服务端从登录会话取得身份。
- **用户与权限**。管理员搜索用户、启停账号、批量授权业务域、设置到期时间，查看某用户的有效权限、覆盖表数和变更记录。
- **业务域**。显示每个域的表数、授权人数和待归类表数。新增元数据版本前可预览归属变更。
- **查数和元数据**。页面只显示有权访问的表和示例。多域用户可在会话里缩小本轮范围。模型配置和测试连接仅管理员可操作，普通用户从已启用的模型中选择。

### 后端的权限检查

| 检查位置 | 行为 |
| --- | --- |
| 接口入口 | 校验登录和操作权限。列表、详情、变更、流式查数和会话接口共用同一份授权判断。按当前账号读取已生效授权，用户提交的域只能进一步缩小范围 |
| 元数据与模型输入 | 在检索排序前限制候选表。血缘只沿可见节点展开，关联、加工条件和样例须核对涉及的表，来源不明的证据暂不使用。只将范围内的元数据交给已批准处理该类元数据的模型连接 |
| SQL 与流式输出 | 复用 SQL 解析器提取整条 SQL 实际读取的底层表。任何未授权、未归类或解析不明确的表都阻止 SQL 交付和执行。普通 SQL 校验失败路径、修正提示及 SSE 轨迹同样过滤域外表名和细节 |
| 数据执行 | SQLite 模拟库沿用只读连接，再基于转换后的物理表名核对允许读取的表。物理名映射必须唯一。接真实数仓时，为执行连接配置对应范围的只读库权限，再验证应用和数据库两层权限一致 |
| 会话与历史 | 所有读写按会话所有者过滤。返回历史或复用上一轮上下文前，重新校验每轮关联的数据范围。旧会话先隔离，待核实所有者及数据范围后再迁移 |

启动查询时绑定本轮授权和元数据快照，避免同一轮使用多个版本的表归属。在模型发送、实际执行及返回受保护内容前检查账号和授权是否变化。已撤权的流终止后续阶段。历史会话如包含当前权限已失效的轮次，一期隐藏该会话的业务内容并阻止续问。新增授权可按业务规则重新开放可验证的历史会话。

## 💡 可迁移的设计

人员权限与表归属是两套独立的映射，类似 ETL 中按有效日期关联人员维表与数据域清单。人员调岗只需调整授权。新表上线只需在元数据发布前完成域归属。权限策略可复用于元数据浏览、NL2SQL、历史会话和执行层。

## 👨‍💻 实施顺序

1. **盘点归属**。为项目域和经费域各选一批表确认归属，确认一期公共维表和允许跨域关联的范围。用元数据版本固定试点表清单，出具归属覆盖和变更报表。
2. **增加账号与授权**。建立登录、有效域查询、管理角色与会话所有者约束。备份旧会话，对未经归属确认的会话暂时隔离。
3. **接入查询和元数据**。把授权表范围传到召回、证据和血缘，集中检查 SQL 和执行路径。检索或流水线若缓存权限范围，缓存键包含元数据版本和权限范围，防止账号间复用。
4. **模拟库验收**。用项目域、经费域、跨域、无授权和管理员账号，通过页面和 API 跑同一套用例。通过后再评估真实数仓的连接账号和授权。

## ⚠️ 验收与常见遗漏

| 验收项 | 建议通过条件 |
| --- | --- |
| 元数据 | 试点开放表归属确认率 100%。搜索、字段详情、血缘和示例返回的域外信息为 0 |
| SQL 与执行 | 授权、无授权、跨域和未归类用例 100% 符合授权矩阵。域外 SQL 交付和执行次数为 0 |
| 会话与流式 | 他人会话访问成功数为 0。撤权后，历史回读、追问、流式结果和模型上下文复用的回归用例 100% 通过 |
| 变更 | 元数据增表、改域和撤权用例 100% 通过。授权变更后首个新请求使用新规则 |
| 查询效果 | 对项目域、经费域各取至少 5 道已知答案的问题，检查召回、生成 SQL 和模拟结果。记录授权前后的通过率及耗时 |

一期需定下表归属清单的维护人、公共维表范围和跨域授权审批人。当前为设计评审稿，验收项是拟定指标。
