# 洛杉矶站为什么只显示 DeepSeek

## 📦 目标

核对洛杉矶站是否使用本地最新工作区代码，以及 GPT 模型为何未出现在下拉框中。

## 📖 讲透

界面从 `/nl2sql/models` 获取选项。后端的 `available_models()` 根据每家服务商是否配置对应 API Key 决定显示哪些模型。类比 ETL：作业模板里有某个数据源的处理逻辑，但运行环境没配置该数据源凭据，就不会把它列为可用来源。

## 🔧 选型

当前运行配置有 DeepSeek 凭据，因此可选默认的 `deepseek-chat` 和 `deepseek-flash`；没有 OpenAI Key，因此隐藏代码中登记的 `gpt-6.1-terra`。本机项目配置存在 OpenAI Key，但本机和服务器是两套独立环境。

## 💡 可迁移

部署新版本时，程序、运行配置和数据是三套不同对象。代码摘要一致不代表每个环境的密钥、默认模型及网络都一致；不能仅凭界面缺少模型判断代码过时。

## 👨‍💻 核对结果

2026-10-29 核对，部署快照所含文件与本地同名文件摘要差异为 0；线上 `config.py` 和模型服务文件摘要也与本地相同。服务器不含 OpenAI Key 配置项；不带凭据访问 OpenAI 模型接口得到 HTTP 401，表明当时接口可达，但不证明密钥有效、模型权限或余额可用。本轮未传输或使用 OpenAI Key，未调用模型生成。

## ⚠️ 常见坑

只配置 Key 可以让选项显示，不代表模型调用一定成功；还需确认密钥权限、额度、模型可用性和接口结果。密钥应保存在权限受限的运行配置中，不写入仓库、笔记或对话。
