# 统一模型配置页面

## 📦 目标

提供独立模型配置页面，用统一表单新增模型，并在同一页面修改原有千问实际型号。

## 📖 讲透

模型配置类似 ETL 的数据源登记：显示名称是会话里看到的入口，服务商决定使用哪一套连接，模型代码是发给接口的实际型号。会话保存入口，提交时解析为服务商和型号；同名型号来自不同服务商时客户端分别缓存。

## 🔧 选型

支持现有五家服务商，使用服务端既有地址和密钥；页面不读取或保存密钥，只显示是否配置。自定义模型存入会话库并随会话备份，支持编辑和停用；原有千问入口兼容此前配置和旧会话。

## 💡 可迁移

把逻辑入口、服务商与具体型号拆开，可以在不重启服务的情况下变更配置。配置有变时，后续请求按服务商和具体型号选择客户端，避免缓存继续使用旧型号。

## 👨‍💻 代码

`nl2sql/model_settings.py` 保存模型配置；`main.py` 暴露配置和模型列表接口并解析每轮选择；`config.py` 按服务商构造连接；前端新增模型配置页面并保留会话内选择。

## ⚠️ 常见坑

- 服务商显示已配置密钥，并不代表账号有模型权限、免费额度可用，或该模型兼容当前 JSON 输出和非思考调用。
- 已停用或缺少服务商密钥的模型不能在新查询中使用；原有会话会提示重新选择。
- 当前表单使用已支持服务商的既有连接，不支持从页面新增任意接口地址或密钥。

## 自定义接口接入

- 📦 目标。新增模型默认填写 Base URL、Model ID 和 API Key，显示名称可选。预设连接作为快捷选项。
- 📖 原理。会话仍保存模型入口。自定义入口解析到服务端保存的地址和密钥，修改配置会更新连接版本，后续查询使用新配置。
- 🔧 选型。支持公开 HTTPS 的 OpenAI 兼容 Chat Completions 接口，输入完整 `/chat/completions` 路径时自动提取 Base URL。请求连接固定在校验后的公网 IP，TLS 校验配置域名。
- 💡 可迁移。服务端会话库保存加密凭据，解密钥匙保存在会话库旁的私有文件。跨主机恢复需通过安全渠道迁移该文件，或在目标机器重新填写 API Key。
- 👨‍💻 代码。新增 `nl2sql/model_connection.py`，配置和密钥写入在 `nl2sql/model_settings.py`，请求校验错误和配置响应省略密钥。
- ⚠️ 常见坑。编辑时留空会保留已保存的密钥。更换 URL 需要重新填写。新增配置和修改配置在隔离环境用假密钥验证，真实模型能力以实际调用为准。

## 测试连接和模型维护

- 📦 目标。新增和编辑模型时先测试当前填写的连接。列表中的内置模型和自定义模型均可编辑、删除。
- 📖 讲透。像在 ETL 调度前用数据源配置执行一条短查询，测试按钮向填写的模型发送一条简短消息。测试使用表单当前值，返回服务商 HTTP 状态、耗时和原因。配置在点击保存后生效。
- 🔧 选型。自定义接口沿用正式查询的公开 HTTPS 连接校验。预设服务商使用已有连接。编辑自定义模型时，地址一致且密钥留空则在服务端复用已保存密钥，响应遮盖密钥。
- 💡 可迁移。会话保存模型入口 ID。编辑时沿用该 ID，下一问使用新配置。删除时清除模型配置及随配置保存的密钥，内置项额外保存删除标记，避免由默认配置重新生成。历史消息保留，选中该入口的会话需要重新选择。
- 👨‍💻 代码。连接测试由 `main.py` 接收表单，经 `nl2sql/model_connection.py` 发出请求。 `nl2sql/model_settings.py` 合并内置和已保存的模型，编辑与删除在 SQLite 事务内处理。
- ⚠️ 常见坑。连接测试只验证当前账号、地址和型号能否处理这一次请求。模型的 SQL 生成质量和结构化输出能力仍需在查数流程中验证。

## 设置默认模型

- 📦 目标。模型列表可将当前可用于查数的模型设为默认，并展示当前默认项。
- 📖 讲透。像 ETL 调度模板里的默认连接，新会话首次提交时读取服务端默认入口。单个会话选过模型后，按该会话保存的入口查数。
- 🔧 选型。默认入口 ID 存在 SQLite 的 `model_settings`。受控模式仅管理员可设置，候选范围与查数接口一致。
- 💡 可迁移。配置持久化与会话选择分开。原有资料库缺少默认配置时，沿用服务端原默认与既有回退规则。
- 👨‍💻 代码。`nl2sql/model_settings.py` 在写事务内校验并保存默认入口，模型列表和查数路由读取同一选择结果。模型配置页保存后刷新列表，会话首次使用默认时获取最新值。
- ⚠️ 常见坑。默认模型停用后会回退，重新启用可恢复保存的选择。删除默认模型会清除相应的默认设置。
